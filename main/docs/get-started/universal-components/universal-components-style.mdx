Auth0 Universal Components are built on a flexible design system that utilizes [Tailwind CSS](https://tailwindcss.com/docs/installation/using-vite) and [Radix UI primitives](https://www.radix-ui.com/primitives/docs/overview/introduction). Styling is orchestrated through the [`Auth0ComponentProvider`](/docs/get-started/universal-components/auth0-component-provider) to allow you to choose between high-level presets or fine-grained CSS variable overrides.

This architecture ensures that your identity flows look and feel like native parts of your application.

## CSS setup

Select your CSS integration path. This choice determines your import and the variable names you use for color overrides throughout this guide.

### Get started

Import the pre-built scoped stylesheet. This path works with any framework and alongside any existing Tailwind version (or none at all).

<Tabs>
  <Tab title="React (SPA)">

Import in your application entry point (e.g., `main.tsx`):

```tsx
import "@auth0/universal-components-react/styles";
```

Add your brand color:

```css
:root {
  --auth0-primary: #4f46e5; /* your brand color */
  --auth0-primary-foreground: #ffffff; /* text on buttons */
}
```

Done. All buttons, links, and active states now use your brand.

### Get started

Auth0 Universal Components work natively with Tailwind v4 (including shadcn). Instead of importing a pre-built stylesheet, your own Tailwind build generates the component CSS. Requires Tailwind v4. If you're on Tailwind v3, use the **CSS** tab.

<Tabs>
  <Tab title="React (SPA)">

1. Add the imports to your CSS file:

```css
@import "tailwindcss";
@import "@auth0/universal-components-react/tailwind";
@import "@auth0/universal-components-core/styles/globals.css";
```

@theme inline {

  --color-muted-foreground: var(--muted-foreground);

## Customization overview

Auth0 Universal Components support four customization methods. Use the one that fits your use case, or combine them — each layer overrides the previous.

<table class="table">
  <thead>
    <tr>
      <th>Method</th>
      <th>Scope</th>
      <th>When to use</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>Theme presets</strong></td>
      <td>Global</td>
      <td>Switch between built-in design variants (default, minimal, rounded)</td>
    </tr>
    <tr>
      <td><strong>CSS variables</strong></td>
      <td>Global</td>
      <td>Simple brand customization in your stylesheet</td>
    </tr>
    <tr>
      <td><strong><code>themeSettings.variables</code></strong></td>
      <td>Global</td>
      <td>Programmatic overrides — dynamic theming, per-tenant branding</td>
    </tr>
    <tr>
      <td><strong><code>styling</code> prop</strong></td>
      <td>Per-component</td>
      <td>Targeted overrides for a specific component instance</td>
    </tr>
  </tbody>
</table>

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
**Naming rule:** `themeSettings.variables` and the `styling` prop always use `--auth0-*` prefixed names for colors (e.g., `--auth0-primary`), regardless of your CSS setup. Only stylesheet overrides differ — `--auth0-*` with the CSS path, bare `--primary` with Tailwind v4.

</Callout>

## Theme presets

Pass `themeSettings` to `Auth0ComponentProvider` to switch between built-in themes.

```tsx
<Auth0ComponentProvider
  themeSettings={{
    mode: "light", // 'light' | 'dark'
    theme: "default", // 'default' | 'minimal' | 'rounded'
  }}
>
  <App />
</Auth0ComponentProvider>
```

</Callout>

## Provider-level overrides (`themeSettings.variables`)

Set CSS variables programmatically on the provider. This is useful for dynamic theming — for example, changing brand colors per tenant or user preference. These overrides take precedence over your stylesheet.

```tsx
<Auth0ComponentProvider
  themeSettings={{
    mode: "light",
    theme: "default",
    variables: {
      common: {
        "--radius-lg": "12px",
        "--font-size-body": "0.875rem",
      },
      light: {
        "--auth0-primary": "#4f46e5",
        "--auth0-primary-foreground": "#ffffff",
        "--auth0-background": "#fafafa",
      },
      dark: {
        "--auth0-primary": "#818cf8",
        "--auth0-background": "#121212",
      },
    },
  }}
>
  <App />
</Auth0ComponentProvider>
```

- Use `common` for border radius and typography overrides.
- Use `light` and `dark` for colors, status colors, and shadows.
- Color variables always use `--auth0-*` prefixed names.

<Accordion title="All available variables for themeSettings.variables">

**`common` (shared across light and dark modes)**

Typography: `--font-size-page-header`, `--font-size-page-description`, `--font-size-heading`, `--font-size-title`, `--font-size-subtitle`, `--font-size-body`, `--font-size-paragraph`, `--font-size-label`

Border radius: `--radius-xs`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl`, `--radius-2xl`, `--radius-3xl`, `--radius-4xl`, `--radius-5xl`, `--radius-6xl`, `--radius-7xl`, `--radius-8xl`, `--radius-9xl`

**`light` and `dark` (identical key sets)**

Bridge colors: `--auth0-background`, `--auth0-foreground`, `--auth0-card`, `--auth0-card-foreground`, `--auth0-primary`, `--auth0-primary-foreground`, `--auth0-secondary`, `--auth0-secondary-foreground`, `--auth0-accent`, `--auth0-accent-foreground`, `--auth0-muted`, `--auth0-muted-foreground`, `--auth0-destructive`, `--auth0-destructive-foreground`, `--auth0-popover`, `--auth0-popover-foreground`, `--auth0-input`, `--auth0-border`, `--auth0-ring`

Status colors: `--color-page`, `--color-info`, `--color-info-foreground`, `--color-success`, `--color-success-foreground`, `--color-warning`, `--color-warning-foreground`, `--color-destructive-border`, `--color-popover-border`, `--color-input-foreground`, `--color-input-muted`

Shadows: See the [Shadows](#shadows) section for the full list.

</Accordion>

## Component-level overrides (`styling` prop)

Every component accepts a `styling` prop for targeted overrides without affecting other components.

```tsx
<SsoProviderTable
  styling={{
    variables: {
      common: {
        "--radius-lg": "16px",
      },
      light: {
        "--auth0-primary": "#059669",
        "--auth0-card": "#f8fafc",
      },
      dark: {
        "--auth0-primary": "#34d399",
        "--auth0-card": "#1e293b",
      },
    },
    classes: {
      "SsoProviderTable-header": "shadow-lg",
      "SsoProviderTable-table": "rounded-xl",
    },
  }}
/>
```

- `variables` — CSS custom property overrides scoped to the component. Same structure as `themeSettings.variables`. Color variables always use `--auth0-*` prefixed names.
- `classes` — Tailwind or custom classes applied to specific component parts.

## Dark mode

The components automatically respond to the `mode` setting in `themeSettings`.

<Tabs>
  <Tab title="React (SPA)">

Sync with your app's dark mode state:

```tsx
function App() {
  const [isDark, setIsDark] = useState(false);

  return (
    <Auth0ComponentProvider
      themeSettings={{
        mode: isDark ? "dark" : "light",
      }}
    >
      <YourApp />
    </Auth0ComponentProvider>
  );
}
```

Or use system preference:

```tsx
const prefersDark = window.matchMedia("(prefers-color-scheme: dark)").matches;

<Auth0ComponentProvider
  themeSettings={{ mode: prefersDark ? "dark" : "light" }}
>
```

  </Tab>

  <Tab title="Next.js">

Include your proxy mode props alongside `themeSettings` on `Auth0ComponentProvider`:

```tsx
<Auth0ComponentProvider
  mode="proxy"
  domain="your-tenant.auth0.com"
  proxyConfig={{ loginPath: "/auth/login" }}
  themeSettings={{
    mode: isDark ? "dark" : "light",
  }}
>
  <YourApp />
</Auth0ComponentProvider>
```

See [Configure Auth0ComponentProvider](/docs/get-started/universal-components/auth0-component-provider) for the full Next.js proxy mode setup.

  </Tab>
</Tabs>

Provide separate color palettes for each mode using `themeSettings.variables`:

```tsx
<Auth0ComponentProvider
  themeSettings={{
    mode: isDark ? "dark" : "light",
    variables: {
      light: {
        "--auth0-primary": "#4f46e5",
        "--auth0-background": "#ffffff",
      },
      dark: {
        "--auth0-primary": "#818cf8",
        "--auth0-background": "#121212",
      },
    },
  }}
>
```

The provider automatically applies the correct set of variables based on the active mode.
